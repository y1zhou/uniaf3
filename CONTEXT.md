# UniAF3 Input Context

UniAF3 describes prediction inputs for AlphaFold3-family models using a unified
configuration language.

## Language

**Structure File**:
A coordinate file, such as PDB or mmCIF, that may contain polymer sequences, modeled residues, ligands, ions, and solvent.
_Avoid_: template file when used as the prediction target source

**Structure-Derived Config**:
A UniAF3 config inferred from a Structure File.
_Avoid_: parsed structure, extracted structure

**Prediction Target Sequence**:
The complete polymer sequence intended for prediction, including residues not present in coordinates when the structure declares them.
_Avoid_: full sequence

**Observed Structure Sequence**:
The polymer residues present in the coordinate model.
_Avoid_: coordinate sequence, modeled sequence

**Molecular Entity**:
A distinct polymer, ligand, or glycan species that may appear as one or more chain/subchain copies in a Structure File.
_Avoid_: molecule when counting copies, chain when referring to species

**Entity Copy**:
One chain or subchain occurrence of a Molecular Entity in a Structure File.
_Avoid_: duplicate, instance

**Author Chain ID**:
The chain identifier assigned by the structure depositor and used by users when selecting which parts of a Structure File to import.
_Avoid_: label asym ID when describing user-facing filters

**Entity Chain ID**:
A collision-free chain or subchain identifier assigned to an Entity Copy and used as the UniAF3 sequence entry ID.
_Avoid_: author chain ID when referring to generated config IDs

**Ligand Inclusion**:
The explicit choice to include CCD Ligands that belong to selected Author Chain IDs.
_Avoid_: automatic ligand import when a chain filter is active

**CCD Ligand**:
A non-polymer Molecular Entity represented by one or more CCD residue codes in the prediction input.
_Avoid_: SMILES ligand when the Structure File only provides CCD residue identity

**Polymer Modification**:
A non-standard polymer residue represented as a canonical sequence position plus a CCD code.
_Avoid_: ligand, mutation

**Structure Connection**:
A relationship between atoms recorded in a Structure File, such as a covalent link, disulfide, metal coordination, hydrogen bond, or contact.
_Avoid_: bond when the relationship may be non-covalent

**Covalent Link**:
A Structure Connection that should be represented as a UniAF3 covalent bond.
_Avoid_: contact, metal coordination

**Non-Covalent Contact**:
A Structure Connection that may be converted to a pairwise contact restraint or a pocket restraint only when the user requests that interpretation.
_Avoid_: covalent bond

**Pairwise Contact Restraint**:
A restraint generated from one Non-Covalent Contact between two atoms or residues.
_Avoid_: pocket when the contact is not grouped around a binder

**Pocket Restraint**:
A restraint generated by grouping Non-Covalent Contacts around one ligand binder and its contacted polymer residues.
_Avoid_: pairwise contact when the user wants ligand-centered grouping

**UniAF3 Sequence Position**:
A 1-based residue position in the UniAF3 sequence entry, independent of author residue numbering in a Structure File.
_Avoid_: PDB residue number, author residue number

**Solvent**:
Water molecules and other solvent records that are normally not part of the prediction target.
_Avoid_: ligand when referring to water

## Relationships

- A **Structure-Derived Config** is inferred from one **Structure File**
- A **Structure File** may contain both a **Prediction Target Sequence** and an **Observed Structure Sequence** for the same chain
- A **Prediction Target Sequence** is preferred for prediction input unless the user explicitly requests the **Observed Structure Sequence**
- A **Molecular Entity** may have one or more **Entity Copies**
- A **Structure-Derived Config** represents repeated **Entity Copies** as one UniAF3 sequence entry with multiple IDs when the copies describe the same **Molecular Entity**
- User-supplied Structure File filters use **Author Chain IDs**, while generated UniAF3 IDs use **Entity Chain IDs**
- Whole-structure import includes supported **CCD Ligands** by default; when **Author Chain IDs** are filtered, **CCD Ligands** in those chains require explicit **Ligand Inclusion**
- A **CCD Ligand** is imported from non-water non-polymer residues; **Solvent** is excluded unless the user explicitly requests it
- A **Polymer Modification** is detected by comparing observed residue CCD codes against the canonical residue at the same position when a **Prediction Target Sequence** is available
- A **Structure Connection** is imported as a **Covalent Link** only when the file marks it as covalent; **Non-Covalent Contacts** require an explicit user-selected restraint interpretation
- A **Non-Covalent Contact** can become a **Pairwise Contact Restraint** directly or contribute to a ligand-centered **Pocket Restraint** when one side is a ligand and the other is polymer
- Bonds and restraints in a **Structure-Derived Config** use **UniAF3 Sequence Positions**, not author residue numbering from the Structure File

## Example dialogue

> **Dev:** "Chain A is missing the first 14 residues in the coordinates. Should the generated config include them?"
> **Domain expert:** "Yes, use the Prediction Target Sequence by default; only use the Observed Structure Sequence when the user asks for coordinate-only import."
>
> **Dev:** "Chains A and C are both hemoglobin alpha chains. Should they become two config entries?"
> **Domain expert:** "No — they are two Entity Copies of the same Molecular Entity, so represent them as one entry with both chain IDs."
>
> **Dev:** "Should a chain filter use mmCIF label asym IDs or the chain IDs the depositor used?"
> **Domain expert:** "Use Author Chain IDs; those are the IDs users recognize when selecting chains."
>
> **Dev:** "If a HEM ligand is under author chain A, can its UniAF3 ID also be A?"
> **Domain expert:** "No — generated IDs use Entity Chain IDs so polymer and ligand copies stay unique."
>
> **Dev:** "If I select author chain A, should its HEM ligand come along automatically?"
> **Domain expert:** "No — selected chains bring polymer content; ligand import for those chains requires Ligand Inclusion."
>
> **Dev:** "The file contains four HEM groups and hundreds of waters. Are all of those ligands?"
> **Domain expert:** "The HEM groups are CCD Ligands; the waters are Solvent and should stay out unless explicitly requested."
>
> **Dev:** "The coordinates contain MSE where the declared sequence has methionine. Is that a ligand?"
> **Domain expert:** "No — that is a Polymer Modification at the methionine position."
>
> **Dev:** "The file has a metal coordination record between HEM and histidine. Should that become a covalent bond?"
> **Domain expert:** "No — that is a Non-Covalent Contact unless the user asks to convert it into a contact or pocket restraint."
>
> **Dev:** "If the user asks for pockets, what does a HEM-histidine contact mean?"
> **Domain expert:** "Treat HEM as the binder and group the contacted polymer residues into a Pocket Restraint."
>
> **Dev:** "The source file says this histidine is residue 88. Is the config residue index also 88?"
> **Domain expert:** "Only if 88 is the UniAF3 Sequence Position; author residue numbering is not carried into the restraint index."

## Flagged ambiguities

- "sequence" can mean either **Prediction Target Sequence** or **Observed Structure Sequence**; resolved: structure-derived configs use **Prediction Target Sequence** by default with a user-controlled option for **Observed Structure Sequence**.
- "chain" can mean a molecular species or a single occurrence; resolved: use **Molecular Entity** for the species and **Entity Copy** for the occurrence.
- "chain ID" can mean depositor author IDs or entity/subchain IDs; resolved: user-facing filters use **Author Chain IDs** and generated UniAF3 entries use **Entity Chain IDs**.
- Chain filtering and ligand filtering can be conflated; resolved: **Ligand Inclusion** is explicit when filtering by Author Chain ID.
- "ligand" can be too broad in a Structure File; resolved: import non-water non-polymers as **CCD Ligands** and treat water as **Solvent**.
- Modified polymer residues can be mistaken for separate ligands; resolved: represent them as **Polymer Modifications** when they map to positions in the polymer sequence.
- "bond" can describe both covalent and non-covalent structure annotations; resolved: use **Covalent Link** only for covalent UniAF3 bonds and **Non-Covalent Contact** for optional restraint conversion.
- Non-covalent structure annotations can be interpreted two ways; resolved: users choose **Pairwise Contact Restraints** or ligand-centered **Pocket Restraints** explicitly.
- Structure residue numbers can differ from prediction sequence positions; resolved: output uses **UniAF3 Sequence Positions**.
